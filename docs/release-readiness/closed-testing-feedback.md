# Closed Testing Feedback Loop

## Tester 招募

目标 tester：

- 使用白噪音、助眠声音或专注音频的人。
- Android 13+ 用户优先。
- 至少包含一台国产 Android 设备和一台 Pixel / 原生系统设备。
- 有蓝牙耳机或音箱使用习惯的 tester 优先。

最低要求：

- 如账号适用 Google Play 新个人开发者要求，至少 12 名 tester 连续 opt-in 14 天。
- 建议招募 15-20 人，预留中途退出或不活跃风险。
- 发布 owner 需要记录 tester opt-in 日期、活跃反馈和 production access 申请回答素材。

## 测试说明模板

可复制给 tester：

```text
请测试 WhiteNoisePro 的以下路径：

1. 打开应用后，直接播放默认混音。
2. 进入 Mixer，查看当前声音层和音量。
3. 进入 Library，浏览并搜索声音。
4. 设置 30 分钟 timer，检查播放状态。
5. 锁屏或切到后台，确认声音是否继续播放。
6. 使用耳机或系统媒体控制暂停 / 恢复。
7. 进入 Settings，查看隐私和播放设置是否清晰。
8. 确认 Settings 是否清楚表达：无账号、无广告、偏好本地保存、第一方本地声音、后台媒体控制不用于营销通知。

请反馈：

- 哪一步让你困惑？
- 声音是否舒适，有无明显循环断点？
- 后台播放是否稳定？
- 30/45 分钟入睡 timer 是否容易找到？
- 你是否愿意睡前继续使用？
- 是否有任何文字、按钮或权限说明不可信？
```

## 反馈分类

- P0：崩溃、无法播放、无法退出播放、严重误导隐私/权限。
- P1：后台播放中断、timer 不可信、声音 loop 明显刺耳、主流程无法理解。
- P2：UI 拥挤、文案不清晰、分类不符合预期、设置项困惑。
- P3：偏好建议、声音内容建议、未来功能。

## 迭代节奏

- Day 0：发布 closed testing build，发送测试说明。
- Day 2-3：收集早期安装和启动问题。
- Day 7：整理中期反馈，修复 P0/P1。
- Day 12-14：确认 tester opt-in 连续性，准备 production access 回答。
- Day 14+：提交生产访问申请或继续 closed testing 修复。

## Production Access 回答草稿字段

- tester 招募方式。
- tester 数量和活跃情况。
- tester 是否覆盖核心功能。
- 主要反馈主题。
- 已修复问题。
- 未修复但接受的风险。
- 判断应用已 ready 的依据。
