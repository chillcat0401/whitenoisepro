# 差异化功能发散(2026-06-10)

前提判断:Google Play 的真正闸门是 14 天封闭测试期,而测试期内**可以持续发新版本**。所以"本周上架"与"继续加功能"不冲突——今天用现有功能开始计时,差异化功能作为测试期内的更新包推送,生产发布时反而带着更强的卖点。结论:**可以加,且应该加,但不为任何功能推迟开始计时。**

## A. 本周现实可做(按 性价比 排序)

### A1. 无限噪声实验室 ⭐ 最强差异化(约 1.5 天)
我们有竞品没有的资产:**噪声是设备端实时合成的,不是音频文件**。把合成参数暴露成一个「音色」滑杆(频谱倾斜 0 dB/oct=白噪 ↔ -3=粉噪 ↔ -6=棕噪,连续可调),用户拖到哪里就生成哪里的噪声,可保存为"我的音色"。
- 实现:NoiseSynthesizer 增加 tilt 参数(一阶滤波系数插值),缓存按参数哈希命名,UI 一个滑杆。
- 卖点文案:"别人给你 3 种噪声,我们给你无限种。"
- 鸿蒙伏笔:参数化声音 = 几个字节,手表端可本地合成,不需要传输音频流。

### A2. 混音骰子(约 0.5 天)
声音库右上角骰子按钮:按「1 层底噪 + 1~2 层主纹理 + 0~1 层点缀」规则加权随机生成混音并自动命名(「雷雨夜的列车」「深夜咖啡馆」)。21 个声音的组合空间靠它被用户探索,也喂内容给"最近使用"。纯 commonMain 逻辑,可单测。

### A3. 场景预设包(约 0.25 天,纯数据)
6~8 个精调开箱混音:雨夜列车、深夜咖啡馆、夏夜门廊、机舱浅眠、溪畔读书、炉边冬夜。零代码风险,商店截图立刻更有故事感。
- 鸿蒙伏笔:每个预设天然对应一张**服务卡片**(桌面一键播放),也是手表/车机的最小控制单元。

### A4. 音浪呼吸引导(约 1 天,建议测试期更新)
开启后主音量按 6 次/分钟的节律轻微起伏(±15%),声音本身变成呼吸引导器——不用睁眼看动画,纯听觉跟随。复用现有 timerFadeFactor 音量通路。白噪音品类几乎无人做声学呼吸引导,且与"睡前"场景完美咬合。

### A5. 床头超暗时钟(约 1 天,可延后)
播放中长按进入:纯黑底 + 暗红大时钟 + 剩余定时,亮度压到系统最低之下。床头常亮场景的刚需,但对 OLED 烧屏和电量要文案提示。

## B. 鸿蒙设备特性伏笔(不实现,只影响今天的架构姿势)

| 鸿蒙形态 | 对应能力 | 今天要保持的姿势 |
|---|---|---|
| 服务卡片/万能卡片 | 桌面一键播放场景 | 预设=纯数据(已满足) |
| 手表独立播放 | 本地合成噪声,不传流 | 声音=参数或小文件(A1 强化此路线) |
| 多设备流转(接续) | 手机→平板→音箱无缝接续 | 播放状态可序列化(AppSnapshot 已满足) |
| 车机/智慧屏 | 极简控制面 + 场景直达 | 控制逻辑留在 commonMain,UI 薄壳 |

核心架构结论:**内容=数据,声音=参数或小文件**——这条线守住,鸿蒙全形态都是薄壳移植。

## C. 推荐执行序

1. 本周(不影响计时):A3 预设包 → A2 骰子 → A1 噪声实验室。
2. 封闭测试期第 1 个更新:A4 呼吸引导 + 真机反馈修复。
3. 生产发布带齐 A1-A4,商店文案主打「无限噪声 + 场景化混音」。
4. A5 看测试反馈决定。
