# Explore: 规格与实现回归

## 输入

- 全部 11 个 OpenSpec 归档。
- 13 份现行规格。
- `PROJECT_PROTOCOL.md`。
- 初始 Figma MVP 规划与第三方产品评审。
- 当前 commonMain、androidMain 和测试代码。

## 方案比较

### A. 只修规格

将未实现行为从 spec 删除。

优点：改动最小。  
缺点：会降低原始 MVP 能力目标，掩盖 Mixer、Timer 和 Saved Mixes 的真实缺口。

### B. 只修实现

补齐所有行为，不处理冲突规格。

优点：产品能力提高。  
缺点：Restore Purchases 和通知权限仍互相矛盾，后续审计继续误报。

### C. 实现与规格同步收敛

补齐仍符合总体规划的核心行为，同时修订已被后续决策取代的规格。

优点：保留 MVP 目标，恢复可追踪性。  
缺点：涉及多个小功能，需要严格分任务回归。

## 决策

采用方案 C。保持现有架构，不增加依赖，不扩展到隐私网页、商店素材或 HarmonyOS。
