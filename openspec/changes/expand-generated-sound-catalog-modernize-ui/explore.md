# Explore: 扩展生成声音目录与现代化 UI

## 背景

已归档的 `2026-06-07-publishable-audio-baseline` 明确选择第一方确定性生成音频，原因是可发布、可复现、可审计，并避免第三方录音授权不确定性。当前实现已经包含白噪、粉噪、棕噪和柔和风扇四个 WAV，但目录仍显得单薄，UI 多处按钮使用文字占位，整体视觉偏基础。

## 素材来源探索

### 方案 A：继续第一方程序化生成

用现有 `tools/generate_mvp_audio.mjs` 扩展雨声、海浪、森林、壁炉等环境声。所有资产由固定 seed 和算法生成，继续记录文件、哈希、QA 指标和所有权说明。

优点：

- 无第三方录音、采样和授权链路。
- 可以自动生成、验证和重新生成。
- 与当前发布基线一致，适合快速进入 closed testing。

限制：

- 声音真实感弱于专业现场录音。
- 需要主观试听，避免合成声音刺耳或疲劳。

### 方案 B：从 CC0 / royalty-free 平台抓取

候选来源包括 Freesound、Pixabay、ZapSplat、Sonniss GDC 包等。可作为后续素材候选，但每个文件都需要保存来源 URL、license snapshot、作者、署名要求、Google Play 与中国大陆分发覆盖情况。

优点：

- 真实感可能更高。
- 可以覆盖更多自然声类型。

风险：

- 授权条款可能变化。
- 部分平台素材需要署名、账户或禁止二次分发。
- 自动 fetch 无法替代人工版权审核。

### 方案 C：在线素材服务

运行时下载或流式播放会引入网络、缓存、隐私和可用性风险，不适合作为当前离线优先 MVP。

## UI 风格探索

当前暗色 token 符合夜间友好方向，但 UI 缺少图标系统和层次：底部导航只有文字，按钮用“设/时/调/删”等文字，占位感较强。

可行改进：

- 在 shared Compose 中提供轻量 `AppIcon`，用 `Canvas` 绘制常用图标，避免新增平台依赖。
- 让声音图标根据 `iconKey` 呈现雨、海浪、树、火焰、风扇、噪声等符号意图。
- 更新主题 token，引入更现代的低亮背景、蓝绿色主色、暖色强调和更细的边框/选中态。
- 底部导航、Mini Player、Hero、Library 卡片从文字占位改为图标化控件。

## 推荐

本次采用方案 A：由 Codex 在本地扩展第一方生成资产并实现 UI icon 化。外部素材来源记录为后续路线，不在本次直接 fetch 到发布包中，避免把未审核授权引入 APK。
